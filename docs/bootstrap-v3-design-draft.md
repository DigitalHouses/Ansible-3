# Новый bootstrap Ansible-3: анализ и проект решения

**Статус:** DRAFT — анализ исходников и вариант для согласования, **не реализация**. **Дата:** 04.11.2026.
**Норма:** [ANSIBLE_STANDARDS.md](../ANSIBLE_STANDARDS.md), согласованные S01/S02/S03/S04/S05/S08/S13.

## Цель

Из чистого Proxmox VE создать **один собственный site runner LXC** и получить рабочие Ansible + Semaphore с начальной конфигурацией дома. Разработка ведётся отдельно в DEV; bootstrap не устанавливает в site runner Codex/Remote Desktop Commander/MCP.

## Согласованное решение: загрузочный репозиторий

- **Единственный загрузочный и основной репозиторий:** публичный `DigitalHouses/Ansible-3` (bootstrap, Ansible-роли, Semaphore-интеграция и каталог задач).
- Старый публичный `DigitalHouses/dh_ansible` — только Legacy/audit; он не используется как источник новой установки.
- `DigitalHouses/dev-infra` — приватный, только для среды разработки DEV, не загрузочный.
- Приватные репозитории отдельных домов содержат собственную конфигурацию; их подключение выполняется отдельной задачей после первичной установки.
- **№00 «Обновить список задач»** создаётся bootstrap и берёт каталог из того же `Ansible-3` (не из site-репозитория и не из отдельного bootstrap-репозитория). Способ обновления посредством штатных API/Ansible-модулей проектируется отдельно, без watchers.
- Исходную версию установки нужно фиксировать release/tag или конкретным commit; правила обновления каталога №00 требуют отдельной реализации.

## Предлагаемая минимальная схема

```text
root@pve: запустить маленький bootstrap Bash с явными site/CTID/IP/параметрами
       |
       +-- pveam/pct: создать чистый Debian LXC и запустить
       |
       +-- в LXC: установить git + штатный ansible-core
       |            получить Ansible-3 из Git
       |            выполнить playbook начальной установки
       |                   |
       |                   +-- Semaphore + системная служба
       |                   +-- локальный inventory/проект/site
       |                   +-- initial admin + минимальная интеграция DEV
       |
       +-- вывести адрес Semaphore, ID LXC и инструкцию первого входа
```

**Обоснование:** bootstrap Bash необходим только до появления Ansible (создание CT и установка самого Ansible). Он не должен превращаться во второй исполнитель инфраструктурных ролей. Дальше состояние описано в Ansible YAML; используются `ansible.builtin.*`, поддерживаемые коллекции и, где нет модуля, официальная CLI/API-команда.

### Предлагаемые границы Bootstrap

- **Включить:** создание LXC; базовое окружение Debian; Ansible; Semaphore; системный сервис; начальное project/inventory; путь первоначальной авторизации; нужный API-доступ DEV; ясный отчёт.
- **Не включать:** Cloudflare Access/Tunnel для множества сервисов, PVE storage, медиасервер/PBS, создание задач этих продуктов, Codex/MCP/Remote Commander, старые watchers, Python-модули/обёртки, сложный Fleet/Vault.
- **Отдельные задачи после Bootstrap:** объединённая №05 (ввод + проверка необходимых credentials); site-repo; конфигурация PVE; поэтапные задачи Cloudflare; медиа VM; PBS.
- **Чёткая граница удаления:** bootstrap не перезаписывает существующий CTID и не удаляет чужие ресурсы. Повторный вызов на занятом CTID блокируется; обычные Ansible-операции после создания должны допускать безопасный повтор.

### Неподтверждённое — согласовать до кода

1. Контракт запуска: какие обязательные аргументы `site_id`, CTID, IP/CIDR, bridge, gateway, storage, ресурсы CT; и какой минимальный интерфейс команды удобен владельцу.
2. Как штатно обеспечить первоначальные учётные данные Semaphore и создание `dev-automation` с временной ролью Owner; **первичный защищённый канал передачи API-доступа в DEV пока не определён** (это зафиксировано в dev-infra).
3. Как предоставлять необходимый PVE-доступ runner, не перенося в bootstrap собственные Python-скрипты доверия.
4. Реализация №00: точное правило обновления существующих шаблонов, обработка удалённых задач и pin версии каталога. Наличие №00 и единый источник `Ansible-3` уже **согласованы**.

## Проверка и критерии готовности

- **Static:** синтаксис Bash, `ansible-playbook --syntax-check`, `ansible-lint` при наличии. Отсутствующий тест помечать `NOT RUN`.
- **Fresh E2E:** в согласованном *отдельном* тестовом CTID/IP появляется LXC с правильными network/hostname/startup; доступны Ansible и Semaphore; вход и выполнение безопасного шаблона успешны; DEV читает результаты и может штатно создать/запустить разрешённое задание.
- **Повтор:** применение Ansible без лишних изменений; повтор создания уже существующего CT не затирает его.
- **Безопасность:** никакого собственного Python, секретов в Git/логах или изменений CT1199/CT1231/CT1254, иных VM, дисков и PVE storage вне согласованной области.
- **Пока НЕ выполнено:** новый bootstrap не написан, E2E не запускался, параметры и спорные решения не согласованы.
