# Codex — инструкции проекта Ansible-3

## Границы

- Работай только над согласованной задачей в репозитории **DigitalHouses/Ansible-3**. Текущая рабочая копия на отдельном **DEV CT1254**: `/home/dev/projects/Ansible-3`. Не использовать Legacy или site runner как среду разработки.
- `ANSIBLE_STANDARDS.md` — основной стандарт. Учитывай разницу между правилами «СОГЛАСОВАНО» и «ПРЕДЛОЖЕНИЕ»; не выдавай предложения за решения владельца.
- Старый `DigitalHouses/dh_ansible` (read-only копия на DEV: `/home/dev/projects/dh_ansible`) и действующая инфраструктура не входят в область изменения, если владелец явно не определил иное. Исторический CT1199 Legacy нельзя использовать для выполнения задач по умолчанию.
- Не придумывай IP, VMID, названия дисков, пароли, параметры Cloudflare или решения архитектуры. Если существенное решение не согласовано — остановись и обозначь выбор.
- Используй штатный Ansible и поддерживаемые коллекции. Не создавай собственный Python, shell-оркестраторы, workers или новые службы без отдельного согласования.

## Рабочий цикл

1. Прочитай относящиеся к задаче файлы и выясни фактический путь от исходников до шаблона Semaphore. **Исторические шаблоны проекта `serzhan-home` на CT1231/Legacy не являются новым runner Ansible-3; правка Ansible-3 сама по себе их не обновляет.**
2. Реализуй только согласованное изменение. Для Ansible используй подходящие проверки синтаксиса и lint, если инструменты установлены; отсутствие тестов не называй успешной проверкой.
3. Для чтения состояния используй штатный доступ к Semaphore **только после фактического подключения целевого site runner к DEV**. Исторический MCP CT1231 не является текущим доступом. Не запускать Legacy Semaphore автоматически. Не выводи секреты и полный необезличенный журнал без необходимости.
4. После настройки MCP/API DEV → site runner запускай `semaphore/create_task` **только когда явно дано задание выполнить конкретный шаблон**, проверено соответствие проекта, шаблона, playbook и репозитория, и штатный клиент разрешил требуемое подтверждение. Никогда не отключай approval и не обходи блокировку через curl, Bash или другой агент.
5. После разрешённого запуска получи ID, дождись окончания через `wait_for_task` (или доступные штатные инструменты), прочитай итоговый статус, ошибки и `PLAY RECAP`. При ошибке локализуй причину, исправь в надлежащем репозитории и повторяй запуск только в рамках разрешённой задачи и после проверки источника исполняемого playbook.
6. В отчёте различай: **код изменён**, **код проверен локально**, **шаблон запущен**, **результат принят**. Укажи ID запуска, финальный статус, `changed/failed/unreachable`, существенные пропуски и оставшиеся риски.

## Пределы действий

- Не трогай другие VM/LXC, диски, данные, ZFS-пулы, PBS/backup, DNS/Cloudflare и credentials без явной области работ. Удаление или стирание данных всегда требует конкретного разрешения владельца.
- Не меняй настройки безопасности Codex/MCP, не отключай подтверждения и не подменяй Semaphore непосредственным Ansible CLI.
- Не создавай коммиты и не отправляй изменения в GitHub, если действие не входит в утверждённую задачу; показывай итоговый diff.
